# ADR 0123: Licensing change governance (maker-checker, licence lifecycle, lock order)

Status: ACCEPTED as the engineering design on branch `claude/licensing-jurisdiction-completion` (migrations 0176-0179). Items marked INTERIM await the human answers in `docs/plans/licensing-owner-decision-requests.md`. This ADR is not a legal opinion and approves no jurisdiction or licence.

## Context
ADR 0006 fixes the hybrid model (`under_platform_licence` / `own_licence`, composite FK `tenants_licence_matches_model`; no universal licence flag). The licensing audit (`docs/plans/licensing-audit-core.md`) found that licence create/bind, licence status and dates, country ceilings, operating-country policies and tenant jurisdiction configs were single-actor, ungoverned or had no writer, and that licence expiry raised no alert.

## Decision
1. **One primitive**: `licensing_change_requests` / `licensing_change_approvals` over a closed registry `licensing_change_kinds` (FORCE RLS, no write policy). The DB classifier `licensing_change_classify` decides widening vs narrowing; the application cannot choose.
2. **Widening** needs two approvals from distinct Persons, each at most 24 h old, from `platform_admin` only (INTERIM answer to HDR-M-1); the requester can never approve or reject their own request; **narrowing** is single-actor. Execution re-classifies (LC024) and requires a signed actor proof (ADR 0110) bound to the request id and payload hash; the executed request carries the proofs, so no new proof-operation family is added (security re-review: sound).
3. **Governed tables**: `licences` (INSERT in 0177, UPDATE in 0178), `tenants` licence columns, `tenant_jurisdiction_configs` (append-only, tenant read-only), `licence_country_ceilings`, `operating_country_policies`. Triggers named `zz_licensing_change_governed*` sort last among BEFORE row triggers (pinned by test) and raise LC040 unless an executed request of this transaction matches the row write exactly. Identity columns of a licence are immutable (LC042).
4. **History**: `licence_versions` is append-only, written by a SECURITY DEFINER writer; attribution (`changed_by`, `change_request_id`) is read from the executed request, never from a session setting (0179). Owner-path writes carry NULL/NULL, which is the break-glass marker.
5. **Lifecycle**: hourly sweep raises `licence.expired` (P1) and `licence.expiring` (P2, 30-day window INTERIM); sweep failure raises `licence.sweep_failed` (P1) and unmonitored licences `licence.unmonitored` (P2). No auto-suspension (INTERIM). A revoked licence is `expired` plus a reason code (INTERIM).
6. **Launch governance** (ADR 0112 amendment): hard failure `H-2:licensing_status_contradicts_licence_registry`; a licence read error refuses; the casino launch/bootstrap gate `casino.CheckLaunchStatusGate` refuses (HTTP 409 `TENANT_OR_BRAND_NOT_ACTIVE`, audit `casino.launch_denied_by_status`) for non-active tenant/brand, in demo mode too. Licence validity stays an acknowledgeable readiness item (owner decision 15).
7. **Behaviour under suspension/expiry** (INTERIM, Q12): new deposits, casino launch/bets, sportsbook bets and registration stop; withdrawals, payouts, settlement, wins and rollbacks of already-placed bets continue.
8. **Lock order** (ledger-finance C3, ADR 0082 addendum): licensing-change request row -> licence row -> tenant row -> (never ledger projection rows). No licensing write path takes a wallet/ledger lock, and no ledger path takes a licensing-change lock; the market/licence read on the bet path is a plain read inside the same transaction and takes no row lock.

## Consequences
Reinstating, extending or clearing an expiry now answers 202 (pending approval), not 200. `reason_code` on licence PUTs must be a code (1..64 of `[A-Za-z0-9_.:-]`). A licence create no longer returns a licence id synchronously. Break-glass (actor-proof issuer unavailable): operator-only owner-credential procedure in `docs/runbooks/licence-lifecycle.md`; creates no new access.
