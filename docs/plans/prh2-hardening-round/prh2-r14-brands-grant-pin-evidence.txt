Tests
-----
(1) TestBrandsGrantPin_RuntimeHoldsUpdate_GateStatementSucceeds - POSITIVE pin:
    exact grant set DELETE,INSERT,SELECT,UPDATE; has_table_privilege
    S/I/U/D true, TRUNCATE/REFERENCES/TRIGGER false; the gate's exact
    statement inside WithTenant returns 'active'; RequireActiveForPayment-
    Initiation returns nil, all as igaming_runtime.
(2) TestBrandsGrantPin_UpdatePrivilegeDoesNotOpenCrossTenantOrTenantlessWrites:
    tenant A session -> UPDATE name/status of tenant B's brand: 0 rows, no
    error (USING filter); plain SELECT of B's brand succeeds (public read) but
    FOR SHARE (gate stmt with B's or A's tenant id, and without tenant
    predicate) returns no row (UPDATE policy USING applies to locking reads);
    gate returns ErrNotActiveForPaymentInitiation; B's row unchanged (owner
    re-read). Re-tenanting A's brand into B: 42501 "new row violates
    row-level security policy for table "brands"" (WITH CHECK). No tenant
    context (app.tenant_id unset AND set to ''): targeted and unbounded
    UPDATEs affect 0 rows, no error; gate stmt returns no row; transaction
    COMMITTED and both rows verified unchanged. Mechanism: NULLIF(...)::uuid
    is NULL, USING evaluates NULL, rows filtered.
(3) TestBrandsGrantPin_GateFailsClosedWithoutUpdate_ScratchOnly: throwaway
    scratchdb database, migrated; control: gate stmt 'active'; owner REVOKE
    UPDATE ON brands FROM igaming_runtime (scratch DB only); then gate stmt ->
    42501 "permission denied for table brands"; RequireActiveForPayment-
    Initiation -> error carrying 42501 (never nil, never "active"); plain
    SELECT still succeeds (dependency is the FOR SHARE clause). The scratch
    database is dropped on cleanup.
    NOTE: the gate's error after a revoke is a wrapped read error
    ("tenant: read brand status: ..."), NOT ErrNotActiveForPaymentInitiation.
    It is fail-closed (non-nil); how each HTTP caller maps a non-sentinel
    error (presumably 5xx) was not re-verified in this round.
