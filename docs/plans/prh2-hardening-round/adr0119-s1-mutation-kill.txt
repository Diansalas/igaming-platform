JUSTIFICATIONS
--------------------------------------------------------------------------------------------------------------
K19 stored MAC length not checked in verifyUnder
    hmac.Equal returns false for inputs of different length, so removing the explicit len(stored) != MACBytes
    guard cannot change any result. Kept as an explicit fail-closed guard. Equivalent.
S07 token decoding not strict (RawURLEncoding without .Strict())
    ParseToken first requires exactly 64 characters. 64 x 6 = 384 = 48 x 8 bits, so there are no trailing bits
    for strictness to reject; the other non-strict difference is that CR and LF are skipped, and a 64-character
    string containing one decodes to fewer than 48 bytes, which the length check refuses. Equivalent.
R02 non-ASCII bytes not refused explicitly in NormaliseRecoveryCode
    Every byte >= 0x80 also fails the Crockford-alphabet check that follows, so the explicit branch documents
    intent only (Unicode case mapping is never applied). The non-ASCII inputs of TestNormaliseRecoveryCode
    (U+00CB, U+0131, U+212A) are refused either way. Equivalent.
P09 zero window start treated as an open window (!start.IsZero() removed in windowOpen)
    time.Time{} is year 1; now.Sub(zero) saturates to the maximum Duration, which is never below the 15-minute or
    24-hour window, so the window reads as expired exactly as with the guard. Equivalent.
