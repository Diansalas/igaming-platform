JUSTIFICATIONS
--------------------------------------------------------------------------------------------------------------
K19 stored MAC length not checked in verifyUnder
    hmac.Equal returns false for inputs of different length, so removing the explicit length guard cannot change
    any result. Kept as an explicit fail-closed guard. Equivalent.
S02 Token.Format removed
    Since C2 the token material is reachable only through an unexported closure. Without Format, verbs that bypass
    String (%d, %x on the struct) render the struct's only field, a func value, as an address; String, GoString,
    LogValue and MarshalJSON still redact. The redaction test therefore still passes: Format is now defence in
    depth, and its removal is behaviour-equivalent for leakage. Kept.
S07 token decoding not strict (RawURLEncoding without .Strict())
    ParseToken first requires exactly 64 characters: 64 x 6 = 384 = 48 x 8 bits, so there are no trailing bits for
    strictness to reject; CR/LF skipping makes the decoded length short, which the length check refuses. Equivalent.
R02 non-ASCII bytes not refused explicitly in NormaliseRecoveryCode
    Every byte >= 0x80 also fails the Crockford-alphabet check that follows. Equivalent.
P09 zero window start treated as an open window
    time.Time{} is year 1; now.Sub(zero) saturates to the maximum Duration, never below a window. Equivalent.
