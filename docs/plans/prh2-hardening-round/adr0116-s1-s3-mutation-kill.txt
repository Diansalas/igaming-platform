Justified survivors (12)
------------------------
A9  authorize: grantee scope not matched (AND g.grantee_scope = v_grant_scope removed).
    EQUIVALENT. The predicate also pins g.grantee_staff_id = v.actor, and a staff id exists in exactly one scope (a tenant staff
    row or a platform staff row), so a grant of that staff id always carries that staff's own scope. The scope term cannot
    exclude a row the staff-id term keeps. (The same predicate in aml_officer_quorum is NOT redundant: it counts other staff;
    A5 pins it.)
A13 authorize: personless actor admitted.
    REDUNDANT BY CONSTRUCTION. An in-force aml_officer grant requires a K1 request that captured grantee_person_id (0112, R-4
    distinct-Person rule), and the grant is joined through that request in the quorum. I found no path to a grant for a staff
    row with a NULL person_id, so the actor check cannot be reached with one. Kept as a fail-closed backstop.
H4  aml_hold_active ignores the tenant.
    EQUIVALENT under FORCE ROW LEVEL SECURITY: the function runs as the table owner, whose only policy
    (aml_owner_session) restricts rows to aml_session_tenant(), and the function already refuses p_tenant <> session tenant
    (AM026, killed mutant H9). The tenant term cannot narrow the result further.
H19 lift: a confirmed_sanctions hold is liftable through the plain path (the function-level refusal removed).
    EQUIVALENT in effect. The plain path then inserts a lift without an approval event, and aml_hold_lifts_guard refuses it with
    the same SQLSTATE (AM006; mutants H17/C18 killed). Two layers, one observable outcome.
C10 approval: the proposer's own ACTOR may approve (actor-id check removed).
    EQUIVALENT. The Person check that follows (C11, killed) refuses with the same SQLSTATE (AM011); an actor row has exactly one
    person, so actor equality implies Person equality. The test TestGuards_FourEyesTriggerDirect/self approval still pins the
    outcome.
C13 approval: kind binding removed from the content-binding comparison.
    EQUIVALENT. The same comparison also compares subject_hold_id and external_filing_reference, and the table shape CHECKs make the
    proposal kind a function of those two columns ((kind = lift_hold) = (subject_hold_id IS NOT NULL), (kind = close_sar_filed) =
    (external_filing_reference IS NOT NULL)); so any kind mismatch is also a mismatch of one of the other terms.
C15 approval: an already-lifted hold re-approvable (the trigger's AM006 backstop removed).
    UNREACHABLE. The earlier invalidation check ("a hold changed since the proposal", which counts a LIFT after the proposal as a
    change) fires first with AM012; TestGuards_SecondApprovalOfAnAlreadyLiftedHold pins that the second approval is refused as
    stale and never surfaces a unique violation from aml_hold_lifts.
C16 approval: from_status unchecked for closures.
    UNREACHABLE. A close proposal is only accepted from sar_decision_pending, the approval must be the event immediately after it,
    so the case status cannot differ at approval time, and the shape CHECK pins from_status = 'sar_decision_pending' for close kinds.
C23 CAS: stale expected sequence allowed in aml_case_lock_for_write.
    EQUIVALENT in effect. The events trigger independently requires seq = last + 1 and raises the same SQLSTATE (AM012); mutant C1
    (trigger check removed) is KILLED, and the function CAS is the earlier of two identical refusals.
C27 queue limit unbounded (SQL side).
    REDUNDANT. internal/aml.Service.CaseQueue refuses limits outside 1..100 before any SQL runs (ErrInvalidInput), and the SQL
    function is revoked from every role except through the proof-bound API. Kept as a backstop for a future caller.
L3  lint: IBAN check off.
    REDUNDANT BY CONSTRUCTION. Every IBAN contains a run of >= 9 digits (separators and letters aside, the shortest national
    BBANs still contain one) and the digit-run rule (L8, killed) refuses it with the same error.
L9  lint: PAN (Luhn) check off.
    REDUNDANT BY CONSTRUCTION. A 13-19 digit card number always contains a run of >= 9 digits, which the digit-run rule refuses
    with the same error. The Luhn rule documents intent and refuses digit groups the run rule would split with letters.
