Justified survivors
-------------------
H02a  Dropping the revoked / replaced check after the FOR UPDATE read is caught by the second, independent guard: the
      UPDATE is `WHERE id = $1 AND revoked_at IS NULL AND replaced_by_session_id IS NULL`, so a revoked or replaced row
      updates 0 rows and StepUpStaffSession returns ErrStepUpNotChainHead (fail closed) - the same observable result.
      Both guards are kept deliberately (defence in depth); the test exercises the behaviour (revoked row refused,
      untouched), which no single-guard mutant can change. Equivalent by construction.
R09   The acting approver's id is added explicitly to the K2 A8 set. Its approval row is inserted earlier in the same
      transaction, so its id is already in the set through decided_by; removing the explicit id is equivalent today.
      Kept so the re-assertion does not depend on the order of the approval insert (ADR 0082 A9 item 3).
