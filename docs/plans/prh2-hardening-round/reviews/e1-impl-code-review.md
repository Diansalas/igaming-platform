## VERDICT: NOT READY for merge (two confirmed correctness bugs; new tests fail/flake in the CI integration step)
- **F1 HIGH required**: the new tests interfere across packages: CI runs `go test -race -tags=integration ./...` with packages in parallel against ONE database (`.github/workflows/ci.yml:264`); `resetOutbox` (`internal/kyc/outbox_helpers_integration_test.go:96-104`, via `newRig` at `outbox_rig_integration_test.go:47`) and `purgeKYCOutbox` (`internal/httpserver/kyc_outbox_testhelpers_integration_test.go:30-61`) delete EVERY outbox row and run `ALTER TABLE ... DISABLE TRIGGER USER / NO FORCE ROW LEVEL SECURITY` (exclusive table lock); `RunPass` and `drainKYCOutbox` claim due rows from every tenant (one package's worker processes another package's rows); `internal/db` T-ID tests seed due rows other packages' workers claim. Reproduced: `-p 3 -count=3` across kyc, db, httpserver gave 11 kyc, 3 db, 4 httpserver failures ("expected exactly one create outbox row ... got 0"; "every create must reach the vendor exactly once: 2 calls for 12 rows"; `TestKYCWorkerIdentity_T_ID_1` "worker claim: no rows in result set"; `TestKYCOutboxHTTP_...` "got 12" vendor calls; two `40P01` deadlocks on the fixture `ALTER TABLE`); control `-p 1 -count=3` green. Fix: scope test workers to the test's own tenants and never delete globally, or serialize every outbox-touching test across packages (session-level advisory lock taken by every outbox fixture, or a dedicated lane); re-run with `-p` > 1.
- **F2 HIGH required (close with security)**: a test seam commits RLS-opening DDL to the shared DB: `openOutboxPolicies` (`internal/kyc/outbox_rls_integration_test.go:143-155`) commits `CREATE POLICY kso_test_open_all ... FOR ALL USING (true) WITH CHECK (true)`; `disableOutboxGuard` (`:114-135`) commits `DISABLE TRIGGER kyc_submission_outbox_guard_row`; both undone only in `t.Cleanup`: concurrent tests in other packages see the outbox with tenant isolation removed and no guard; a killed test binary leaves the open policy/disabled trigger permanently (`migrate verify` passes with the policy present). Fix: keep the DDL inside an owner transaction that is rolled back (e.g. `SET LOCAL ROLE igaming_runtime` inside it) or probe a temp copy; at minimum a crash-safe sweep at package start.
- **F3 MEDIUM required**: idempotent create can return a stale finished verification (`internal/kyc/outbox.go:280-288`): after the unique-index conflict `existingCreateForPlayer` takes the newest create row in pending/claimed/sent; if the player already has an older `sent` create and the winning create ends `failed_terminal` between the conflict and the read, the query skips the winner and returns the old verification with `existing=true` and HTTP 200, contradicting its doc comment and ADR 0106 §2.10 (retry the insert); proven by probe `TestCRProbe_CreateRace_WinnerTerminal_WithOlderSentCreate` (`existing=true sameAsOld=true`). Validated fix: `SELECT verification_id FROM (SELECT verification_id, state FROM kyc_submission_outbox WHERE tenant_id=$1 AND player_account_id=$2 AND operation='create' ORDER BY created_at DESC, id DESC LIMIT 1) latest WHERE state IN ('pending','claimed','sent')` (probe passes, kyc suite green).
- **F4 MEDIUM required (identity-compliance + security)**: a race sends a vendor SUBMIT with an EMPTY provider reference (the N5 hazard the old code blocked): `hasLiveCreate` (`outbox.go:310-322`) is an unlocked SELECT; the worker prepare cancels a submit only when the verification is still a true orphan `status='unverified' AND ref=''` (`outbox_worker.go:488-491`); scenario: upload reads the create as live; before it commits staff set the orphan to `review_required`; worker cancels the create (`decided_concurrently`) and cascades pending submits (cannot see the upload's uncommitted row); the upload commits a pending submit; next pass claims it; verification not orphan (`review_required`) and not terminal so the worker calls `SubmitVerification` with reference `""`, sending PII documents; proven by probe `TestCRProbe_LateSubmitAfterDecidedConcurrently_EmptyReferenceSent` (`refs=[""]`); old exported `SubmitVerification` refused any empty reference. Validated fix: in prepare cancel when `isOrphan || v.ProviderReference == ""` and/or refuse the call in phase B; optionally read the create row `FOR SHARE` in the upload tx. Explains why mutant N8 survives.
