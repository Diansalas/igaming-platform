# Security DESIGN review: PRH-2 E1 (ADR 0106 PROPOSED + ADR 0095 §38), branch prh2-e1-design @ abced51

Source: security subagent final report (model output, not user input). Condensed record. Design-level + code-level reading; probes on a private DB `sec_e1d` built from `git archive 3517980` (runtime role `igaming_runtime`, neither superuser nor BYPASSRLS), dropped. Not a pen test; real KYC vendor PROVIDER DEPENDENT; implementation needs its own mandatory security review.

## VERDICT: ACCEPT WITH CONDITIONS — implementation must NOT start until ADR 0106 is revised to r2 with the REQUIRED changes; then a short security delta re-check of r2 only
Core design sound: hybrid identity (discovery + claim only); outbox stores only ids and states; split FORCE RLS families, no NULL arm, no FOR ALL, no DELETE; claim forced by trigger + lease; alert raised in-tx from the tenant session so `alerting_session_scope()` is untouched; IC F3 structure holds.

## Findings
- **F1 HIGH REQUIRED (blocks implementation)**: the worker identity inherits NULL-tenant read AND write on older dual-scope tables, contradicting HD-PRH2-11 ("unable to perform unrelated financial/admin operations"). Proven on a private DB with only `app.platform_service_id='kyc_submission_worker'` set: `INSERT INTO staff_users (tenant_id NULL, ..., role 'platform_admin')` succeeded (policy `staff_users.dual_scope_isolation` FOR ALL with arm `tenant_id IS NULL AND app.tenant_id IS NULL`); `INSERT INTO audit_log (tenant_id NULL, actor_type 'system', ...)` succeeded (forged platform audit rows). Catalogue scan: more permissive NULL-arm policies not excluding `app.platform_service_id`: `login_attempts.dual_scope_isolation`, `sessions.session_scoped_insert/update`, `risk_rules.tenant_and_platform_write/_update/_delete_visibility`, `player_restrictions.staff_insert`, SELECT of platform `staff_users` rows (incl. `password_hash`) and platform `audit_log` rows; runtime grants allow it (`deploy/init-app-role.sql:85`). Q-S1 RULING: NOT accepted for `kyc_submission_worker`. Required in 0114: an `AS RESTRICTIVE` fence policy family (SELECT/INSERT/UPDATE/DELETE) with predicate `NULLIF(current_setting('app.platform_service_id', true), '') IS DISTINCT FROM 'kyc_submission_worker'` on every table where the worker session has any read/write beyond public reference data (minimum `staff_users`, `audit_log`, `sessions`, `login_attempts`, `risk_rules`, `player_restrictions`; implementer derives the full list from the catalogue); precedent 0112 `acting_fence_*` restrictive family; A-18 permits restrictive-only generation; no effect on other sessions or the 0077 whitelist tables. Tests: T-ID-2 adds NULL-tenant variants (platform `staff_users` `platform_admin`, platform `audit_log`, `risk_rules` I/U/D, `player_restrictions` staff insert, `sessions`, `login_attempts`); T-ID-3 becomes worker visibility 0 on every table except `kyc_submission_outbox` and an explicit allowlist of public reference tables (`tenants`, `alert_kinds`, jurisdictions) and <= `WithoutTenant` everywhere; catalogue gate: every permissive INSERT/UPDATE/DELETE/ALL policy on any other table has a positive guard the worker never satisfies or the table carries the fence; rewrite §3.3 and §9 R1.
- **F2 MEDIUM pre-existing, NOT E1-blocking (human decision)**: the same NULL-arm write path is open to every `WithoutTenant` session and to `sportsbook_catalogue_sync` and `alert_dispatcher`: any SQL in a `WithoutTenant` tx can create a platform-admin `staff_users` row and forge platform audit rows; RLS does not stop it, only Go discipline does. Register follow-up NULL-ARM-WRITE-1 (NULL-tenant write arms must require a validated platform-admin GUC, as `asset_operation_eligibility` and `open_bet_self_exclusion_policies` siblings do). Security recommends closing before production launch; whether it blocks launch is the human's decision.
- **F3 MEDIUM REQUIRED**: player-triggered amplification of vendor calls and PII processing through async create (§2.6, §7.2): no bound on verifications per player today; with the outbox POST create is a cheap enqueue, every row a distinct `kv:` key; per-tenant cap 20/pass starves other players. Required: at most one live (`pending`/`claimed`) `create` row per player account, repeat create returns the existing orphan verification idempotently (or 409), enforced by the DB or a serialising lock (not check-then-insert); test + mutant.
- **F4 MEDIUM REQUIRED**: pinned provider never re-checked against the tenant's current configuration (§2.5, §2.9, §7.1): a tenant that removes/replaces a KYC vendor still has queued rows sending player data to it. Required: in prepare (P), under tenant RLS, verify `row.provider_id` is still configured (same source as `configuredKYCProvidersSQL`); else no call: `cancelled` with new reason `provider_deconfigured` (or `not_sent` -> terminal); never redirect; test + mutant.
- **F5 MEDIUM REQUIRED**: credential binding mismatch is an integrity signal, not a retryable `not_sent` (§2.8, §4.1): add `last_error_class = credential_binding_mismatch`, straight to `failed_terminal` with no retry, distinct discriminator suffix `<op>:<provider>:binding_mismatch`, and a CHECK on `kyc_submission_outbox.provider_id` `^[A-Za-z0-9_.-]{1,64}$` (alert `provider_id` attribute is copied raw).
- **F6 LOW-MEDIUM REQUIRED**: trigger column pinning explicit for the worker (§2.3, §2.4): worker claim keeps `failed_attempts`, `next_attempt_at`, `last_error_class` (except forced `lease_expired` on re-claim), `cancel_reason`, `terminal_at` equal to OLD (a bug resetting `failed_attempts` would retry forever without terminal state/alert); `last_error_class='deferred_tenant_inactive'` accepted only when `tenants.status <> 'active'` (DB-validated).
- **F7 LOW REQUIRED**: down migration ordering/refusal scope (§5.3): under standalone `psql` autocommit block 1 (Kind removal) commits then block 2 refuses on live rows, leaving table and worker without the Kind (every `failed_terminal` raise lost silently). Run the outbox refusal FIRST or both in one DO block. Q-R5 RULING: refuse while ANY outbox row exists (0110 down precedent; outbox rows are the only durable record of worker claims, §3.5).
- **F8 LOW REQUIRED**: static/test hardening: R2 GUC-spoof static test widened to any non-test occurrence of the literal `app.platform_service_id` outside `internal/db`; new static test: every UPDATE of `kyc_submission_outbox` in non-test Go lives in `internal/kyc/outbox*.go` and every tenant-side UPDATE has `claim_token = $n` in its WHERE; new INV-KYC-OB-4 tamper test (P and C with a tenant id different from the claim's RETURNING return 0 rows, no provider call, no write).
- **F9 LOW REQUIRED**: lease budget must cover prepare: `ValidateForLoop` lease inequality counts the call and phase C but not P; P must run on a bounded context included in the inequality (else lease expires before phase B: double send R3/R11).
- F10 LOW optional: global `seq` leaks platform-wide KYC volume to tenant readers (`kso_tenant_select`); order supersession by `(created_at, id)` or record as accepted residual.
- F11 LOW optional: deterministic phase-C failures (e.g. vendor reference already bound elsewhere, 23505) loop claim -> lease expiry -> re-send PII up to `MaxFailedAttempts`; treat SQLSTATE class 22/23 in apply as terminal `apply_conflict` after in-item retries.
- F12 INFO REQUIRED text: P's `document_set_changed` re-enqueue must use the same `ON CONFLICT ... DO NOTHING` as phase A.
- F13 INFO accepted residuals (record in §9): suspension or staff document rejection landing between P's commit and B's call (at most one send, same as H sweeper); every in-tx-raisable Kind can be raised by any plain tenant session about its own tenant.

## Rulings
Q-S1 NOT accepted (F1 fences required). **Q-S2 APPROVED with conditions** (verified on PG16: plain owner INSERT into `alert_kinds` refused under FORCE RLS; DO block creating the policy, inserting, then raising an injected exception leaves no policy/row; the temporary policy rejects any other Kind value; afterwards policies exactly `{alert_kinds_read_all, alerts_platform_service_dispatcher}`; strictly better than the FORCE toggle rejected in 0048 S-1): SQL literal (no EXECUTE); policy `FOR INSERT` only and `TO CURRENT_USER`; predicate equality on exactly one Kind; CREATE, INSERT, DROP in one DO block; FORCE RLS never toggled; tests 32/37 plus a runtime-role `INSERT INTO alert_kinds` refused after up; the down-migration unseed (`DISABLE TRIGGER` + temporary DELETE policy inside one DO block) accepted on the same atomicity basis; becomes the sanctioned route for later Kinds only under these conditions with security review per Kind. **Q-S3**: `ActorType=system`, `actor_id NULL`, `metadata.platform_service` compiled constant ACCEPTED (matches H sweeper rows `sweeper.go:640,678`, `audit_log_check`); UUIDv5 `service` actor rejected; test that `metadata.platform_service` is present on every row the worker writes. **Q-S4**: claim token in the WHERE CAS is sufficient, GUC not required (any tenant SELECT can read `claim_token`; covered by M1/M2 + F8 static test). Q-R1 acceptable (check for live create must read inside the upload tx). Q-R2 201 + `unverified` acceptable (no outbox internals in the player response). Q-R3 support removal. **Q-R4** no deadlock cycle found (upload holds only FK KEY SHARE; C's NO KEY UPDATE does not conflict; provider-reference unique index partial); conditions: F8 static test, F12, 40P01 propagates through `RaiseGuarded` into bounded phase-C retry, test 16 at `-count` >= 20. Q-R5 refuse on ANY row. HQ-E1-1: fail-closed default supported (no vendor call for suspended/closed tenant, no attempts burned; cancelling closed tenant rows / ever sending for suspended is a human data-processing/contract decision; F6 DB check required either way). HQ-E1-2: p2 acceptable for outage exhaustion; binding mismatch distinguishable (F5); human may raise to p1; nothing pages anyone while ALERT-DELIVERY-1 is OPEN. HQ-E1-3: no security threshold; budget bounded (each retry re-sends PII). HQ-E1-4: outbox rows are the only durable claim record; any future deletion keeps claim history at least as long as audit retention or audits the claim; period is the human's decision. Alert Kind `in_tx_raisable_by_tenant=true` confirmed bounded (`alerts_subject_tenant_raise` forces `subject_tenant_id = app.tenant_id`, `raised_by_scope` forced `tenant`, severity forced from `alert_kinds`, `alerts_guard` allowed keys, flat scalars <= 2048 bytes, dedup per (subject tenant, operation, provider); tenant can only create noise about itself; same exposure as the 14 existing tenant-raisable Kinds; allowlist `{operation, provider_id, last_error_class, outbox_id}` acceptable given F5 charset CHECK).

## Design changes REQUIRED in ADR 0106 r2 before code
1 F1 fence family + rewrite §3.3/§9 R1 + T-ID-2/T-ID-3 + catalogue gate; 2 F3 one live create per player account DB-enforced; 3 F4 provider re-check; 4 F5 `credential_binding_mismatch` + charset CHECK; 5 F6 column pinning + trigger-validated deferral; 6 F7 down ordering + refuse on any row; 7 F8 static/tamper tests; 8 F9 P bounded in lease inequality; 9 F12 ON CONFLICT DO NOTHING; 10 record F2 as registry follow-up (NULL-ARM-WRITE-1), F10/F11/F13 as residuals or adopt.
Missing tests: NULL-tenant write/read denials for the worker (platform `staff_users` insert as `platform_admin`, platform `audit_log` insert, `risk_rules` I/U/D, `player_restrictions` staff insert, `sessions`, `login_attempts`, SELECT of platform `staff_users`/`audit_log`); catalogue fence gate; worker claim cannot change `failed_attempts`/`next_attempt_at`/`last_error_class`/`cancel_reason`/`terminal_at`/`document_ids`; cannot re-claim an unexpired lease; trigger refuses lease > 10 minutes; `deferred_tenant_inactive` refused while tenant active; suspended/closed: mock provider records zero calls; provider de-configured after enqueue: zero calls; binding mismatch immediate terminal with distinct discriminator; per-player create bound under concurrency; INV-KYC-OB-4 tamper test; lost-claim/phase-B error logs contain no vendor reference, credential or raw error text; tenant B cannot raise the KYC Kind with tenant A as subject; runtime-role INSERT into `alert_kinds` refused after up; down: refused down leaves Kind, FORCE RLS and deny trigger intact, refuses when only terminal rows exist; P re-enqueue racing a concurrent upload of the same set: no 23505 abort; every worker-written audit row carries `metadata.platform_service`.
Missing mutants: M22 worker claim resets `failed_attempts`/`next_attempt_at`; M23 re-claim ignores lease expiry; M24 remove worker fence on `staff_users`/`audit_log`; M25 P/C take tenant id from elsewhere than RETURNING or skip `(id, claim_token)` re-select; M26 drop P's provider-configured re-check; M27 binding mismatch retryable; M28 seed policy not dropped; M29 lease upper bound removed from trigger; M30 principal exclusion dropped from tenant write policies; M31 alert attribute outside allowlist (raise swallowed, alert lost); M32 per-player create bound removed; M33 down refusal ordering reverted; M34 deferral accepted while tenant active.
Human decisions (not invented): F2 (does the pre-existing NULL-arm platform-admin write exposure block production launch; security recommends closing before launch); HQ-E1-1..4.
