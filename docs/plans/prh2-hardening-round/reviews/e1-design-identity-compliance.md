## Positions
- Q-R2: 201 + `unverified` acceptable; a staff-visible derived submission state is REQUIRED (compliance console lists orphans as bare `unverified`, `kyc_admin_handlers.go:100`); a coarse player-visible enum (queued/sent/failed/none, no vendor data) recommended (product decides). Player create path must not become an unbounded vendor-call generator: cap/dedupe one live create per player_account.
- Q-R1: confirm with conditions: (a) when create ends failed_terminal/cancelled, pending submit rows cancelled with `verification_not_submitted` + audit (test); (b) documents uploaded onto an orphan whose create fails are stranded (runbook; retention under HQ-E1-4); (c) live-create cap bounds storage amplification.
- Q-R3: agree to remove exported CreateVerification/SubmitVerification; static test must forbid any exported function reaching KYCProvider.CreateVerification/SubmitVerification; sync-behaviour tests rewritten to drive the worker and still assert IC condition 2.
- Q-R5: down must REFUSE while ANY outbox row exists (outside scratch DBs).
- HQ-E1-1: engineering default accepted (no vendor call for non-active tenant, defer without consuming attempts, never cancel, never write status); auto-cancelling a closed tenant's submissions and ever sending for a suspended tenant are HUMAN/LEGAL; deferral must be observable (age gauge + runbook; `claims` increments per deferral cycle, document it). HQ-E1-2: keep p2 as engineering default; compliance-incident status is a HUMAN/COMPLIANCE call; confirm before 0114 ships (changing severity later needs a migration). HQ-E1-3: HUMAN/LEGAL; any deadline is jurisdiction configuration, never a worker constant; retry budget (30s base, cap 30 min, 8 attempts ~1 hour) is a placeholder; prefer not terminating on a short outage. HQ-E1-4: HUMAN/LEGAL; default keep everything, no deletion path.
- KYC-OUTBOX-REQUEUE-1 deferral acceptable ONLY with the staff-visible submission state and runbook; a later requeue must be an audited staff action with reason code via the tenant session and never write a verification status.
