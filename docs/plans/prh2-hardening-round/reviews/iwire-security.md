## Findings
- **S-1 MEDIUM REQUIRED pre-merge** `internal/httpserver/alert_admin_handlers.go:115`: `SELECT ... FROM alerts WHERE id=$1 AND tenant_id IS NULL FOR UPDATE` conflicts with `FOR KEY SHARE` taken by the `alert_occurrences` FK insert, so an ack/resolve blocks (and is blocked by) business transactions raising on the same alert; if the business tx's context expires the error (57014/context) is not swallowed and the dispute/park/posting rolls back because of an alert statement. Probe: with FOR UPDATE held, in-tx raise blocked 2s then aborted the business tx; with FOR NO KEY UPDATE it completed in 27 ms. Fix: `FOR NO KEY UPDATE` + regression test (in-tx raise not blocked while an ack holds the row).
- **S-2 LOW doc REQUIRED pre-merge**: guarantee overstated (ADR 0102 §17.2 ~1431-1432; `internal/payments/alerts.go:17-19`; comments in `drive.go` parkDepositAttempt and `orchestrator.go`): reword to "a deterministic alert-statement failure (22/23/42501/P0001) never rolls back...; transient/lock/cancel classes propagate as any statement in the transaction would".
- **S-3 LOW, REQUIRED before a real channel**: kill-switch `reason_code` free text (`payments_kill_switch_handlers.go:410-424`, DB only bounds octet_length 1-64) goes verbatim into platform P2 payload; social-engineering/PII injection risk once a channel renders attributes. Map to closed token pattern or "nonconforming"; `killSwitchAlertReasonMax=128` dead code and byte-slicing can split UTF-8. Real adapters must render attributes as escaped data.
- **S-4 LOW optional**: failure-path detached raises run before the HTTP response (`deposit_handlers.go`/`casino_handlers.go` `raiseIntegrity`), contradicting ADR §17.2 (~1447); mild amplification under DB distress (admission slot held up to 3 attempts 0/200/800ms). Move after response or correct ADR.
- **S-5 LOW optional**: B-1 static guard checks owners contain InTx and .Flush, not transitive-caller reachability; a new caller via plain WithTenant would pass (fails safe: swallowed alert lost, `alert_raise_no_pending` log). Promote to metric/panic under integration tag.
- **S-6 LOW optional**: authorization layers not each pinned (A1, A1b, A2 survived); A1 stops being redundant once a platform-scoped non-admin role exists. Add: platform-role token with non-nil tenant -> 403; handler test with nil-tenant staff lacking `alert:manage` -> 403.
- **S-7 INFO**: occurrence rows unbounded until ALERT-RETENTION-1 (storage/DB load, not paging storm); keep ALERT-RETENTION-1 open, precondition for real channels + production volume.
- **S-8 INFO**: `alert_admin_handlers.go:165` logs no error class (log SQLSTATE class only); `alertinject` takes ShareRowExclusive on `alerts` per test on shared CI DB and can leave scoped triggers after a crash.
