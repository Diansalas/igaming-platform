## Findings
- **L-1 Low (optional before merge; REQUIRED tracked follow-up + systemic item)**: trigger lookups can be shadowed by a temp table (search_path): `migrations/0114_kyc_submission_outbox.up.sql` lines 125-365 (`kyc_submission_outbox_guard`) unqualified `tenants`, `kyc_verifications`, `kyc_documents`, `kyc_submission_outbox` lookups with no `SET search_path`; reproduced as the runtime role (TEMP privilege): `TEMP TABLE tenants(id, status='suspended')` before the trigger's first use, then a tenant session moved a claimed row to `pending/deferred_tenant_inactive` for an ACTIVE tenant and the trigger accepted it; same technique would get past the INSERT orphan/provider/document checks and the claim's "create live" check. Impact: needs arbitrary SQL as the runtime role and the Go layer independently re-validates: defence-in-depth gap in the "DB-validated" claims (F6 deferral, insert validation), not an exploitable application path; pattern probably systemic in older triggers. Fix: `ALTER FUNCTION ... SET search_path = pg_catalog, public, pg_temp` (pg_temp last) or schema-qualify on both 0114 functions; track a systemic item for other triggers.
- **L-2 Low (REQUIRED tracked follow-up, optional before merge)**: log-redaction test gaps (S5, S5c): `internal/kyc/outbox_worker.go:644` (credential-resolver failure log) and `:744/:782/:957/:1011` (phase-C, apply-conflict, prepare, claim failure logs) have no test catching a regression to raw error text (current code correct: logs nothing or `RedactedProviderErrorDetail`): add a slog-capture test driving each branch with sentinel error text asserting the sentinel never appears.
