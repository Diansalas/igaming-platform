## VERDICT: ACCEPT WITH CONDITIONS (one new Medium F-1 introduced by the delta must be fixed before merge; F-2, F-3 doc items)

- **F-1 MEDIUM REQUIRED pre-merge: a panic now becomes HTTP 200 to the payment provider (callback acknowledged, never redelivered).** Deferred `flushResponse(w)` at `internal/httpserver/deposit_handlers.go:427-428`, `casino_handlers.go:445-446`, `payment_deposit_simulation_handlers.go:339-340` also runs while a panic unwinds; `ResponseController.Flush()` on an unwritten response commits the status line as 200; the outer `recoverMiddleware` `apierror.Write(500)` is then ignored as "superfluous". Payments scenario: defer registered before `alerting.InTx(... ReceiveVerifiedCallback ...)`; any panic in verified-callback processing rolls back the domain tx but the PSP gets 200 and stops redelivering, so the deposit is never credited (only daily reconciliation catches it); before this delta the same panic gave 500 and a retry = regression on the provider-callback partial-failure path. Casino: narrower window (defer after the domain tx) but covers `recordCasinoCallbackRejection` and error-to-response mapping, a retriable rejection could be acked. Simulation: player-facing, low impact. Access log records 500 while the wire carried 200. Required fix: flush only on the non-panicking path, keep the raises running, then re-panic (`p := recover(); if p == nil { flushResponse(w) }; pending Flush; queued raises; if p != nil { panic(p) }`) or an equivalent "flush only if a response was written" guard. Required regression test: a panic injected inside the verified payment webhook path must give wire 5xx, not 200 (casino test recommended). Not affected: kill-switch engage (`payments_kill_switch_handlers.go:728`) and the `writeDepositCallbackError` payload-mismatch branch (`payment_deposit_simulation_handlers.go:267`), which flush explicitly after the response was written.
- **F-2 LOW REQUIRED (doc): N-2 not closed**: ADR 0102 `:1638` §17.7 item 6 still begins "`alert_dispatcher` is the only platform-service identity the binary sets" (false: `cmd/platform-api/main.go:264` uses `db.ServiceSportsbookCatalogueSync`); reword to "the dispatcher uses only `alert_dispatcher`".
- **F-3 LOW REQUIRED (doc; behaviour change is a security improvement)**: `statusRecorder.Unwrap` silently made ADR 0097 A5 effective in production: `webhook_preamble.go:28` `armBodyReadDeadline` -> `http.NewResponseController(w).SetReadDeadline(...)` returned `ErrNotSupported` behind the access-log wrapper, so the per-request body read deadline was never enforced (only server `ReadTimeout` 15s; T11 swaps the seam out). Now it works, and via net/http's background read the request context cancels ~`BodyReadTimeout` after body-read start (10s default, configurable lower) instead of 15s on webhook routes. Fails safe (tx rolls back, 5xx, provider retries; detached post-response alert work unaffected). Required: record in ADR 0097 or §17.10 that A5 was a no-op in production before this change and now bounds the handler context; add a note to `BodyReadTimeout` config validation that it must comfortably exceed worst-case webhook processing time. Optional: test that `SetReadDeadline` reaches the connection through the full chain.
- F-4 INFO/optional: (a) `Unwrap` also exposes Hijack, EnableFullDuplex and deadline setters in-process (no handler uses them today; future use needs review because `statusRecorder` would log 200 for a hijacked connection); (b) the wiring AST test matches only the identifier `alerting` (aliased/dot import evades it; production refusal of `SyntheticComponent` sinks in `NewDispatcher` still not done); (c) §17.10 R-2 note quotes `-skip 'TestResolutionIsolation_'`, documented lanes use `-skip 'TestStoreOutage_DoesNotPinPool|TestResolutionIsolation_'`: quote the full pattern; (d) no response-flush test for the deposit-simulation handler.
