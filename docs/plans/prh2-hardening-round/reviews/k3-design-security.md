## K3 findings
- **R-1 HIGH required**: acting ledger fences under-specified for M2 branches (b),(c): §8.4 says fence triggers call `ledger_governed_fence_allows` "unchanged" but merged 0113 `ledger_entries_governed_fence` hard-codes the K2 shape (looks up `ledger_adjustment_requests` by `'manual_adjustment:'||id`, else CG030): fail-closed (acting M2 cannot work) or, worse, an implementer bypasses the per-entry check for non-`manual_adjustment` types, reopening K2-C1 (arbitrary entries under the governed header). Same gap on accounts: 0113 `ledger_accounts` `acting_insert` allows only `player_cash`/`manual_adjustment` ("K3 widens it") but ADR 0101 never specifies the widening (`withdrawal.Complete` needs `psp_clearing`, `Fail` needs `player_withdrawal_hold`/`player_cash`). Required: per-entry shapes replacing the `ledger_entries_governed_fence` body in 0115 — (b) Step B exactly 2 entries: debit wallet `player_withdrawal_hold`, credit tenant `psp_clearing` (`wallet_id IS NULL`), asset `wr.asset_code`, amount `wr.amount`, one leg per direction; (c) `withdrawal_failed`: debit wallet `player_withdrawal_hold`, credit same wallet `player_cash`, `wr.amount`; widen acting `ledger_accounts` INSERT only to `player_withdrawal_hold` for the executing M2's wallet and `psp_clearing` with `wallet_id IS NULL`, only while an executing M2 exists in this txid; down restores both 0113 bodies and the policy byte-for-byte (add to C-16); K2-C1/C2 analog tests: wrong wallet, wrong amount, third entry, entry appended after `executed` in the same tx.
- **R-2 HIGH required**: reconciliation cannot see M2 resolutions: family T "tenant GUC, no platform GUC" mirroring K2 `tenant_scope_*` (requires `app.principal_id`) leaves the reconciliation stream (`WithTenantSnapshot` sets only `app.tenant_id`, `tenant_rls.go:54`) reading zero executed `m2_*` rows: `pay_declared_paid_unconfirmed` / `pay_declared_not_paid_but_paid` never raised, INV-M-4 silently false, double-payout detector (R-K3-1) disappears. Precedent K2 `tenant_system_read_executed` (`0113:1785`). Required: SELECT-only policy on `payment_manual_resolutions` with `state = 'executed'`, system shape (tenant GUC only; principal, platform-admin, player, platform-service, acting all NULL); no system-shape policy on approvals; run C-7, C-22, C-29 in the real reconciliation session shape as the runtime role; mutant dropping the policy must be killed.
- **R-3 MEDIUM-HIGH required**: DB-guard parity with K2 not stated (§8.2 trigger list omits controls K2's `ledger_adjustment_requests_guard`/`_execution_status` enforce in the DB): explicit parity table covering (i) insert scope `tenant` or `platform_acting` only via `financial_actor_session()`, `NEW.tenant_id` = session tenant; (ii) capability-specific grant at insert and counting (`ledger_adjustment_eligible_grant(..., 'payment_force_resolve:request'|':approve')` with `_invisible_platform_grant` fallback; `financial_acting_session_valid()` is capability-agnostic so a platform principal with only `ledger_adjustment:*` for tenant X passes every K3 acting policy; C-40 does not test this); (iii) S-2(iii) at insert for the requester; (iv) DB-side recount at `pending -> executing` (K2-C3 lesson; §6.3 step-6 recount is executor-side only); (v) refusal of every non-executed exit (`refused_at_execution`/`rejected`/`cancelled`/`expired`) while a ledger transaction exists with key `provider_id:platform-operator-declared:<id>` or `wr.id:failed` with `correlation_id = wr.id` posted in this tx (K2-C1(i)/MA040 analog); (vi) `expires_at` DB-forced; (vii) cancel by requester only, reject only via a same-tx reject decision, `-> executing`/`refused_at_execution` only in the final approval's tx; (viii) server-forced ids (`id`, hence `reserved_provider_tx_id`).
- **R-4 MEDIUM required (Q-SEC-4)**: `payment_attempt_reference_evidence` policy shape and writer binding: a loose "tenant GUC" T policy lets any tenant staff session insert Y rows; a forged Y equal to a reference that already carries a reversal/tombstone clears a standing `pay_captured_unposted` P1 (S4, T-K3-5); pre-planted row can make the real park raise on the UNIQUE "different reference" path (park DoS). Required: split policies — INSERT system shape only (tenant GUC; principal, player, platform-admin, platform-service, acting all NULL); SELECT system shape plus optionally tenant staff for display, never players; no UPDATE/DELETE policy; no NULL arm (`NULLIF(...)::uuid` equality only); DEFERRABLE INITIALLY DEFERRED constraint trigger: at commit the attempt must be `disputed` with `terminal_reason = 'poll_reference_mismatch'` and the park must have happened in this tx.
- **R-5 MEDIUM required**: closed-tenant actor scope for K3 M2: M2 is available for `closed` tenants (§5.1), tenant-scope finance staff remain eligible (staff login does not gate on tenant status, G-T grants stay in force) yet the closed-tenant design says such staff may be uncontrolled (HD-CTF-2). Required: when `tenant_status = 'closed'` (read in-tx at insert, approval and execution) refuse tenant-scope requesters and approvers; only `platform_acting` actors with `payment_force_resolve` grants may act; optional: same for `suspended` or at least one platform approver.
- **R-6 MEDIUM required**: stale approvals (S-11) on a changed factual basis: payload hash does not cover attempt state/terminal reason at submission: pin `attempt_state_at_submission` and `terminal_reason_at_submission` into the payload hash; `refused_at_execution` if either changed; test in C-12b.
