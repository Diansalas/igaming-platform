Survivor classification (honest)
--------------------------------
M2a  EQUIVALENT (defence in depth). The in-memory `attempt.EscalatedAt != nil` pre-check only saves
     the Escalate round trip: with it removed, Escalate's own SQL CAS (`escalated_at IS NULL`) rejects
     the second tick with ErrAttemptStateConflict, which the helper maps to (false, nil) with no audit
     and no alert - identical observable behaviour. The SQL guard is the real control and is killed by
     M2b/M2c; the conflict mapping by M2d.
M8c  EQUIVALENT (defence in depth), same reasoning: Escalate's SQL predicate
     `state NOT IN ('succeeded','declined','rejected','disputed')` yields the same conflict -> (false, nil),
     and every caller short-circuits a terminal row earlier (applyStatusEvidence's
     attemptAwaitingEvidence check; processUnreferenced's fresh re-read).
M5d  NEAR-EQUIVALENT. In processUnreferenced the fresh `!attemptAwaitingEvidence` early return is
     shadowed, for every terminal shape a callback can produce, by the next check (a callback by
     merchant reference binds a provider_reference, so the "reference bound since the lease" return
     fires). It is only observable for a terminal attempt that STILL has no reference, which no test
     hook can produce today (that would need an operator/recon resolution path; out of scope). Without
     the check such a row would reach RescheduleNonTerminal and error (next_action_at is NULL on a
     terminal row) - a loud, safe failure, never a write. Kept as a deliberate explicit guard.

Not-killable-by-design notes
----------------------------

  24h when unset or when the provider is unregistered). first_submitted_at is immutable (trigger), so
  tests age an attempt by shrinking the manifest window to 1ns, never by back-dating the row.
* The control and all mutant runs used the private scratch database only.
