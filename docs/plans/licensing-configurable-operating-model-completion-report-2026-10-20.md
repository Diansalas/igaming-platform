## 8. Remaining risks and limitations (honest)
- First local run had three load-sensitive httpserver failures (isolated rerun green); intermittents on record: `core-rg-recon-aml` hosted shard (once), `TEST-DCONC-INTERMITTENT-1` (open).
- Migrations 0181, 0187, 0188 were edited in place while unreleased; any dev/staging database that applied an earlier version must be rebuilt and never rolled back with its down.
- Worker API (claim/finish/heartbeat) is proof-less (MOCK only); hard prerequisites before any real provider: separate DB principal or system actor, revoke from the runtime role, daily vendor reconciliation, alert route (ALERT-DELIVERY-1 still open; the trapped alert pages nobody until a route exists).
- Sanctions review does not expire beyond the engineering bound of four re-screen intervals (cap 180 days); the fingerprint is worker-supplied (same trust as a forgeable worker clear, bounded by the production environment guard).
- Residence mode `into_open_market` trusts the application's market declaration (documented residual).
- Calendar-conflict RG state: UI offers no loosening, server does not refuse it (policy decision C); play fails closed while the conflict lasts.
- Back Office screens for KYC, residence, withdrawal and AML are exercised end to end against the real API in e2e; visual/browser coverage is Chromium only; no load/performance or accessibility testing; no AWS RPO/RTO or production-provider claim of any kind.
- e2e coverage gaps (from lic21/lic22 records): play-trigger KYC enforcement, pending-determination blocking a deposit at the market gate, the requests/replace route, the 24 h/72 h expiry paths, concurrency.
