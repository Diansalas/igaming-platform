PRH-2 R5 stake-return (Q-GP-5) and tenant-closure guard (Q-GP-1) mutation-kill evidence (2026-10-06)
Branch prh2-r5-stake-return-closure (from d149a64). Migration 0121.

Method. A throwaway copy of the worktree (outside the repository, no .git) was migrated into a private
database (prh2_r5_mut, dropped afterwards) and tested as the runtime role (asserted NOT rolsuper AND NOT
rolbypassrls). For each mutant: apply ONE textual mutation to the copy (migration mutants rebuild the private
database from the mutated migration), run  go test -tags integration -p 1 -run <regex>  on the listed packages
(casino: TestStakeReturn|TestTenantNotActive; sportsbook: TestStakeReturn|TestTenantNotActive|TestTenantClosure;
tenant unit tests for the Go mutants), record KILLED (non-zero exit) or SURVIVED, restore the file from the
worktree and verify with cmp. A CONTROL run of the unmutated copy passed (rc=0) before the batch and after the
restore. The repository working tree was never mutated.

Mutant classes: A = application stake-return exemption (casino requireStakeReturnAllowed/verify, sportsbook
isTerminalStakeReturn/requireTenantForSettlementPosting/verifyVoidReturnsPlacedStake, tenant.GameplayStatus);
D = migration 0121 gameplay backstop (ledger_gameplay_tenant_active_guard and the deferred
ledger_sportsbook_rollback_requires_void constraint trigger); B = migration 0121 closure guard
(tenants_status_change_gate); G = Go closure translation and audit (internal/tenant/status.go).

Note on the two-layer design: removing one application check often leaves the database trigger as a backstop
(and the reverse); a mutant is KILLED when the tests require the clean typed refusal / the exact outcome that only
the mutated layer produces. SURVIVORS are listed and explained at the end; they are equivalent mutants (the other
layer refuses identically) or states unreachable under RLS.

--- notes on the survivors and the strengthened test ---
A02 SURVIVED (equivalent): a casino rollback of a WIN routed through the stake-return gate is still refused,
  because verifyStakeReturnMatchesBet only finds a casino_bet original (no row -> ErrStakeReturnMismatch) and the
  database backstop (D04) independently refuses a rollback of a win. Both layers are individually mutation-killed
  (D04 KILLED; TestStakeReturn_CasinoRollbackOfBetAllowedOnNonActiveTenant and
  TestStakeReturn_CasinoDatabaseBackstopNarrowed pin the refusal).
A07 / D06 SURVIVED (equivalent under RLS): dropping the tenant_id predicate from the original-bet lookup (app) or
  from the backstop's EXISTS does not let another tenant's bet through, because ledger_transactions is FORCE-RLS
  scoped to app.tenant_id (and ledger_entries/ledger_accounts are joined on tenant_id). The predicate is kept as
  defence in depth; cross-tenant isolation is pinned by TestStakeReturn_CasinoCrossTenantIsolation and
  TestStakeReturn_SportsbookCrossTenantIsolation (another tenant's reference tombstones in its own tenant, no
  money moves in either).
A16 / D11 SURVIVED (state unreachable in a test): "tenant row not visible" can only occur under a player-scoped or
  platform-scoped connection, where ledger_transactions RLS already refuses the insert; the fail-closed branch of
  the primitive is covered by TestTenantNotActive_GateFailsClosedWhenTheRowIsNotVisible (R3) and is kept.
D07 first run SURVIVED: a raw rollback reversing the bet's PLACEMENT (not a settlement) paired with a void was not
  covered (the unpaired variant is refused by the deferred trigger anyway). Case 4b was added to
  TestStakeReturn_SportsbookDatabaseBackstop; re-run: D07 KILLED, control rc=0.
