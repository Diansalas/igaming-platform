PRH-2 K1 (ADR 0099 scoped financial capability grants) - mutation-kill evidence
================================================================================
Migration under test: migrations/0112_scoped_financial_capability_grants.{up,down}.sql
Setter under test: internal/db/tenant_rls.go (WithPlatformActingInTenant)
Test DB: private orchestrator scratchpad DB (never the shared CI DB), built via
priv_db.sh from this worktree, per the harness rules in the task brief.

Method for every mutant below:
  1. Edit the migration/Go source in place (the exact hunk is shown).
  2. Rebuild the private DB from source (`priv_db.sh`) for SQL mutants; `go build`
     for the one Go mutant.
  3. Run the specific integration test(s) named as the killer.
  4. Record PASS/FAIL.
  5. `git checkout -- <file>` to restore the exact pre-mutation text.
  6. `git diff <last commit> -- <file> | wc -l` = 0, confirmed byte-identical
     revert, for every mutant below.
  7. Rebuild once more and re-run the killer test to confirm it passes again on
     the restored code.

Honest count: 6 of 9 attempted mutants are independently killed by a dedicated
test that fails only because of that specific removed check. 3 mutants are
"masked": the test suite still passes (the same refused outcome results) but
via a DIFFERENT, independent control in this schema, not the one that was
removed - each is disclosed below, is not a false "kill" claim, and the
underlying SECURITY PROPERTY (the thing the ADR actually cares about) is still
proven to hold in every case, just via a different mechanism than the one
mutated. This is a direct consequence of this migration's own deliberate
belt-and-braces design (e.g. R-1 self-grant and R-4 distinct-Person always
coincide when grantee == requester, since a staff row is always its own
Person) - not a gap.

MUTANT 5 - MASKED (not independently killed; disclosed)
Predicate: self-grant refusal, R-1 (staff_capability_grant_requests_guard)
Change: removed the "IF NEW.grantee_staff_id = v_actor.actor THEN RAISE ...
        (R-1)" block entirely.
Test run: TestCapabilityGrant_A5_SelfAndDistinctPersonRefusals - STILL PASSES
          with the mutant in place.
Why masked: a self-grant is, by construction, always also a same-Person
grant (a staff row's own person_id trivially equals itself), so R-4's
"requester and grantee must be distinct Persons" check (a few lines below R-1
in the same trigger) independently refuses the exact same INSERT with the
same SQLSTATE (CG010), before R-1's absence can ever be observed. There is no
reachable state in this schema where grantee_staff_id = requester but the
grantee's Person differs from the requester's Person - so R-1 is proven,
disclosed defense-in-depth, not a gap: self-grant IS refused end-to-end
(TestCapabilityGrant_A5 passes on the real, unmutated code too, and the ADR's
own go/no-go condition is satisfied), just via R-4's check rather than R-1's
own line. Reverted; byte-identical (0-line diff against the last commit).
