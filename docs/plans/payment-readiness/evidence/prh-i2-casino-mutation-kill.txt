§3. Orchestrator fix-round item 5: raw cause.Error() in append-only audit (2026-09-27)
===========================================================================================

Scope: `casino.launch_failed`'s audit metadata previously stored `cause.Error()` verbatim -
a real adapter's transport error (`*url.Error`) can embed the full request URL, including
a query-string credential, and append-only `audit_log.metadata` must never receive that.
Fixed with a closed `LaunchFailureReason` enum (`provider_unavailable`, `declined`,
`circuit_open`, `credential_unavailable`, `credential_binding_mismatch`, `ctx_cancelled`,
`internal`) stored in place of the raw error text; the underlying cause is still available
to an operator only through `phaseCLogger`'s log line, redacted by the new
`redactedLaunchFailureDetail` (mirrors `internal/payments/gate.go`'s `redactedReason`
without importing it - `*url.Error` reduced to op + timeout/canceled/transport-error
classification, anything unrecognized reduced to a fixed, non-identifying label - stricter
than payments' own fallback, which still echoes `err.Error()` for an unrecognized type).
Grepped the whole `internal/casino` package for other `err.Error()`/`.Error()` writes into
`audit.Record`/`Metadata` - the ONE site was this one; the other `.Error()` call in this
package logs a *phase-C transaction's own* DB error (not the adapter's cause), which is a
log line, never audit.

M18 audit `"reason"` reverted from `string(reason)` to `cause.Error()`: KILLED
[internal/casino/orchestrator.go] by
`go test -tags=integration ./internal/casino/ -run TestLaunchGame_TransportErrorAuditNeverStoresRawErrorText`
    first failure: --- FAIL: TestLaunchGame_TransportErrorAuditNeverStoresRawErrorText
                       "audit metadata leaked the secret-bearing URL:

    (the new test builds a *url.Error carrying a secret-looking query string, calls

§4. CAS-SESSION-EXPIRY-1 (code-reviewer FH-7 re-review, 2026-09-28)
===========================================================================================

Scope: §2/§3's own MEXP survives against the WHOLE casino suite because it is the
INVERSE of what the original submission believed it was testing - the original item-2 fix
(§2 above) applied `now() > expires_at` to a bet against EITHER `active` or `consumed`
(`internal/casino/orchestrator.go` `postBet`). `expires_at` is the un-consumed launch
TOKEN's own TTL (`DefaultLaunchTokenTTL`, 2 minutes, `launch.go`), never an in-play bound -
`consumed` is the ordinary state for the entire lifetime of a real-money round, so every
such round stopped accepting bets ~2 minutes after launch. Fixed: the expiry check now
applies ONLY when `session.Status == LaunchSessionActive`. C4 (revoke CAS misses a
vendor-consumed session, §15.1.2's declined-to-widen closure) is reopened by this fix -
widening `RevokeLaunchSession`'s CAS was investigated and found blocked by the migration
0036/0042 immutability trigger (any `UPDATE` where `OLD.status IN ('consumed','expired',
'revoked')` is rejected, regardless of `NEW.status`) - not implemented; tracked as
CAS-REVOKE-CONSUMED-1 (`docs/governance/task-registry.md`).
