Notes
-----
- M2 is killed by TestINVDEP1_BackstopBranch_PreCheckPassesLedgerIndexFires_DisputesAndCommits, a REAL race
  (the X5 construction: racer A blocked on a held psp_clearing projection row, racer B entering
  postDepositSuccessOrDispute, A commits, B's INSERT hits the 0107 index). No production seam. With M2 applied
  the sentinel propagates as an error, B's transaction rolls back, and the test fails on the error.
- K1 is killed by TestKSCASDiscrim_NonKillSwitchT2ConflictIsNeverRecordedAsKillSwitch: the non-kill-switch
  cause is the T2 sibling-succeeded guard (the intent is already credited when a stray 'created' sibling reaches
  T2). With K1 applied the conflict is recorded as a kill-switch decline instead of surfacing an error.
- Equivalent mutant (not run, by reasoning): dropping the explicit `tenant_id = $1` predicate from
  foreignReferenceBinding. Under FORCE RLS the table already hides other tenants, so no test can distinguish it;
  the predicate is belt and braces. Cross-tenant behaviour is instead pinned by
  TestDepRefConflict_CrossTenantSameStringHasNoEffectOnTheOtherTenant (tenant B reusing A's string neither
  disturbs nor is disturbed by A; no cross-tenant read).
- A pre-existing test fixture had to change: TestRVLF_N2_DriveGo and TestRVLF_N4 build a synthetic Succeeded
  DepositResult. Without the new amount echo they would now hit T10 sync_amount_mismatch before reaching the
  tombstone/T13 branch they exist to test (N2 would have kept passing for the wrong reason). Both fixtures now
  carry Amount/AssetCode, so they exercise their original branch.
- Review-round mutants: C-REDIR-1..3 (security C-1: scrub dropped in each of the two callers, and the helper
  forwarding for every state), C-CB-1 (QA F1), C-ERR-1/2 (code review F1: error-path validation and scrub),
  C-BINDREF-1..3 and C-AUD-1 (LF F-C1, F-C3), C-INTENT-1 (code review F2, stale returned intent), C-UNIFY-1
  (LF F-C2).
- QA F1 mutant note: the callback-during-phase-B ordering cannot be forced to resolve before phase C commits for a
  sync success (nothing is bound until that commit), so the callback tests are sequential and deterministic; the
  "double-post" mutant C-CB-1 changes the callback's disposition after the sync success (applied instead of
  duplicate_effect). A mutant that makes the callback itself post a second time has no code path to mutate: the
  duplicate branch never calls the posting function, and a second posting is additionally refused by the 0107 index.
- Known residual found while writing the F1 tests (not fixed in C): a callback deferred during phase B stays
  unresolved after the sync success posts (ADR 0095 section 34.7).
