Fix: internal/kyc.EvaluateEnforcement now runs every read inside a
SAVEPOINT nested in the caller's transaction (internal/db.
RunReadOnlyInSavepoint, the same pgx.Tx.Begin-on-an-open-Tx mechanism as
internal/db/idempotency.go's IdempotentInsert) and unconditionally rolls
it back afterwards. A genuine Postgres error inside the read (e.g. a
lock_timeout) previously aborted the CALLER's transaction; the caller's
own subsequent attempt to record the resulting `unavailable` decision in
that same transaction then hit SQLSTATE 25P02, producing a raw error
instead of a typed *KYCDeniedError/ErrKYCUnavailable outcome. The fix
applies uniformly to EVERY EvaluateEnforcement call site (withdrawal,
deposit, casino play, sportsbook play) - not only withdrawal - which also
closes ADR 0096 §16.2's LF-I3-5 disclosure (casino/sportsbook decision-row
loss on a genuine DB error during evaluation): with the read now
contained to a savepoint, RecordDecision's own transaction is never
poisoned, so the decision/audit row for a play-path DB failure now
survives exactly like withdrawal's already did.
