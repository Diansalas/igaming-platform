Method. A throwaway copy of the worktree (outside the repository) was migrated into a private database
(g_gamemut, dropped afterwards) and tested as the runtime role (asserted NOT rolsuper AND NOT rolbypassrls).
For each mutant: apply ONE textual mutation to the copy (migration mutants rebuild the private database),
run  go test -tags integration -p 1 -run 'TestTenantNotActive|TestGamePostingsNonActive'  on
./internal/casino ./internal/sportsbook ./internal/httpserver, record KILLED (non-zero exit) or SURVIVED,
restore the file from the worktree and verify with cmp. A CONTROL run of the unmutated copy passed (rc=0)
before each batch. The repository working tree was never mutated.

Entry points mutated: casino postBet, postWin, postRollback (tombstone branch, posted-original branch),
sportsbook PlaceBet, sportsbook lockAndPost (the single choke point of settle, rollback, rollback tombstone,
void of an open bet, void after settlement, i.e. also the staff SimulateSettlementEvent path), the shared
primitive, the casino durable record, the HTTP mappings, and every part of migration 0118.

Note on the two-layer design: removing an application check (M01..M04, M10, M12) leaves the database trigger
as a backstop, so the posting is STILL refused at the database (SQLSTATE GP010) and no money moves; the
mutant is nevertheless killed because the tests require the clean typed refusal, the recorded audit row and
the deterministic response, which only the application check produces.
