## Findings
- **M1 (Medium, J1).** Legacy `signature`-field guard never exercised in KYC (`internal/kyc/orchestrator_webhook_integration_test.go:299-303`) or casino (`internal/httpserver/casino_webhook_tenant_binding_test.go:156-160`): body modified after signing, fails in `Scheme.Verify`, never reaches `kyc/mock_provider.go:202` / `casino/mock.go:425`. Deleting either guard leaves tests green. K5 asserts only `errors.As(*CallbackAuthError)`, never the `Reason`. Fix: sign the legacy-shaped body with the real key; assert `Reason` in every K5 subtest.
- **M2 (Medium, J1 evidence).** R4/J6 mutation-kill record (`08-webhook-test-traceability.md:75-94`) failed with a SQL error (`could not determine data type of parameter $1`), not the predicate assertion. A renumbered mutation is only caught for the wrong reason. Fix: rerun with renumbered placeholders; match the lookup by `FROM kyc_verifications WHERE` + `provider_reference`, not literal `$2`.
- **M3 (Medium, ADR claim false).** ADR 0022 amendment says KYC and casino tenant-binding conformance cases exist (as skips for the first real adapter); `internal/kyc` has no conformance test. Fix: add `internal/kyc/conformance_test.go` or correct the ADR.
- **M4 (Medium, B7).** `kyc_webhook_noop` allow-listed info log not implemented; `_ = result` at `kyc_admin_handlers.go:495`; `ReceiveCallback` does not report applied vs no-op. Fix: return `applied bool`, log `kyc_webhook_noop` (request_id, tenant_id, provider_id only), remove `_ = result` — or rule it out.
- **M5 (Medium, docs).** ADR 0085 §1 "three flags" claim is TRUE drift: main.go derives four Deps flags (incl. `SportsbookSettlementSimulationEnabled`, Stage 10 W1) plus `mockProviderWiring`; `internal/config/config.go:455-467` and the `Environment` list (`:26-45`) also drift. Fix: update ADR 0085 §1 and config.go docs.
- **L1 (Low).** Comments in `casino/mock.go:413-415` and `kyc/mock_provider.go:195-203`, and ADR 0022's scope sentence, say every post-verification rejection is malformed/400, but the legacy field returns `ErrCallbackSignatureInvalid` (401, reason `signature_invalid` — a false forgery-alert signal). Behaviour matches design; fix the text.
- **L2 (Low).** A replayed `outcome: error` KYC callback writes a new audit row each time (`kyc/provider.go:356-366`), contradicting §E's "no audit append" rationale for deferring PAYWH-TS-1. Fix: skip the failure audit when the row is already terminal, or document.
- **L3 (Low, OpenAPI).** Casino 503 claims post-verification only but `CasinoOrchestrator == nil` precedes the preamble; casino 400 omits `ErrBetNotFound`, `ErrLaunchSessionRequired`, `ErrOutcomeNotSucceeded`, `ErrInvalidInput`; KYC 204 lists `outcome: error` among no-ops but it audits; casino contract test's `oversized` check searches the whole path block.
- **L4 (Low).** Casino C4 "EqualSecretResolver" uses no equal-secret resolver (copy of C3); casino conformance cross-tenant case stops before the MAC; unused `genuineBody` with wrong comment.
- **L5 (Low, dead code).** `kyc.ErrUnknownProvider` unreferenced with stale doc; `payments.ValidProviderIDFormat` zero callers; `webhookauth.ProviderIDPattern` exported reassignable `*regexp.Regexp` (process-wide weakening possible). Fix: delete; unexport the pattern.
- **L6 (Low).** Casino `default:` event-type branch (`orchestrator.go:687`) returns a plain error → 500 for a verified caller. Fix: wrap with `ErrCallbackMalformedBody` → 400.
- **L7 (Low, simplification).** Three shapes of the same MOCK resolver (payments wrapper, identical KYC wrapper, casino direct); Sign+SetHeaders repeated three times; `mockWiring` three bools from one value (divergence test tautological), stale "later steps extend this struct" comment; `kycOrchestrator` doc justifies unconditional KYC mock construction "for other purposes" that don't exist, and ADR 0085 says "absent".
- **L8 (Low, architecture note).** `webhookPreamble` and every orchestrator hard-require the domain's MOCK header format before the adapter runs; a real vendor's scheme would be rejected with 401 unless header parsing becomes an adapter/Scheme capability. Payments already had this. Record as a known constraint on the first real adapter.
