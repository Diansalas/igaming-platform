# Casino package: minimum decisions and inputs

Each item: the question, why it is needed, and `casino`'s recommendation. The owner decides. Items are ordered by when
they block (OQ-CAS-01/02 first; the rest at the gate named). Nothing here is decided by this package.

| Id | Needed by | Question | Recommendation |
|---|---|---|---|
| OQ-CAS-01 | C1 | Which casino aggregator(s) are to be evaluated, and may 1 to 2 alternatives go through the same checklist before a commercial relationship is committed? Commercial fit (territories, studios, currencies, fees, licence requirements) cannot be decided from documentation | Yes to a short list of 2 or 3 aggregators or one aggregator plus one direct studio. Run the identical `U-CAS-nn` checklist on each (the mapping is provider-neutral). The owner, not an agent, handles vendor contact |
| OQ-CAS-02 | C1, C2 | (a) Provide or authorize reading the vendor documentation (none is available today). (b) After C1, authorize the adapter build against **recorded fixtures only** (no sandbox call) | (a) Yes: read-only documentation, no account, no credential. (b) Yes, conditional on a C1 go |
| OQ-CAS-03 | C0/C2 | If the vendor cannot speak the platform's callback/bootstrap wire or needs a vendor-shaped response (CAS-G01), or needs a balance route / round-close acknowledgement / combined events (CAS-G02): authorize `architect` + `casino` + `security` to design the additive adapter hooks? | Prefer a vendor whose contract fits with the smallest hook set. If the chosen vendor needs hooks, authorize them as additive, handler-side translation only; do not change `postBet/postWin/postRollback`. Decide only after the documentation shows the need (U-CAS-08/13/14/17/18) |
| OQ-CAS-04 | C1 | First-brand product scope: casino game categories (slots only? table? live?), currencies (fiat only per the 2026-10-15 decision), territories, and whether bonus-funded play is in scope for the first brand | Slots only, fiat only, cash-funded play only for the first sandbox and first brand; bonus-funded play afterwards, once CAS-G04 and LF-10 are decided. This avoids multi-bet rounds and held-disposition rollback entirely |
| OQ-CAS-05 | C2/C5 | Free rounds, jackpots and promo payouts (CAS-G03): exclude such titles/features for the first brand, or fund a design (ADR + ledger-finance + bonus-engine)? | Exclude. Choose or configure titles without them (U-CAS-19) and add a launch refusal for titles flagged with such features. Design it only when a business case exists |
| OQ-CAS-06 | C5 | Round-timeout / abandoned-round policy (CAS-G08): who settles a round the vendor never closes? | Follow the vendor's documented policy once known (U-CAS-34); if the vendor guarantees a final win/rollback for every bet, no sweep is needed. Do not invent a platform timeout that posts money without ledger-finance design |
| OQ-CAS-07 | C5 | Statement source (CAS-G07): what does the vendor provide (API vs file, latency, cut-off, totals) and is the weaker case (file, daily, no record time) acceptable with a timing window? | Decide after C1 from the vendor's documentation, never a guess. Require an API or file with per-transaction ids and a stated coverage horizon. Build the per-(tenant, provider) source registry, stored copy and real mismatch kind with the first source. `ledger-finance` approves any weaker timing semantics explicitly |
| OQ-CAS-08 | C5/C8 | CAS-RECON-SCALE-1: design + ADR for per-run cost before real multi-tenant volume | Required before C9, not before C6 (a synthetic tenant is small). `ledger-finance` + `architect` + `devops` size it from the first brand's expected rounds/day; owner confirms the target |
| OQ-CAS-09 | C5/C8 | CAS-BET-JURISDICTION-RECHECK-1 / mid-session travel (CAS-G05): accept the 4 h session bound (configurable) plus the launch-time evidence, or require a per-bet vendor geolocation signal? | Accept the bound for the first brand, shorten the lifetime per jurisdiction if compliance asks (it is configuration), and revisit when a geolocation vendor is selected (see `../kyc-aml/`). Compliance owns the call; no regulatory value is invented here |
| OQ-CAS-10 | C0 | If the vendor's inbound authentication has no signed timestamp, or places the signature in the body or query (PSP G-01/G-02 apply to casino too): reject that vendor, or authorize an ADR 0022 amendment? | Same as PSP OQ-3: prefer another vendor or vendor-side configuration; authorize `security` + `architect` to design the amendment only if the vendor is otherwise the best fit and the documentation shows it is needed (U-CAS-24) |
| OQ-CAS-11 | C6 | One vendor operator account per tenant (needed for callback tenant binding and per-tenant reconciliation)? | Yes for any tenant that goes live; the first (synthetic) tenant needs one. A shared account cannot bind a tenant |
| OQ-CAS-12 | C6 | Where are non-secret operator/site ids held (PSP G-08)? | In per-tenant provider configuration, with the secret and the signed account id in the credential handle. `security` confirms classification |
| OQ-CAS-13 | C8 | Acceptance of the disclosed consequences: emergency stop is credential revocation and strands open exposure; a suspended tenant's open rounds cannot settle and an unseen-original rollback leaves no tombstone (HD-10.3-4) | Accept with the runbook (mandatory consistency/statement run before a replacement key); revisit only if the vendor's redelivery window is shorter than a plausible suspension |

## Inputs (not decisions) the owner must eventually supply

Listed in `integration-gates.md` ("Exact inputs needed"): vendor documentation, sandbox terms, sandbox credentials
(outbound API, callback signing secret, read-only report) via the secret store, one operator account per tenant, the
published IP ranges, written vendor answers to the open documentation items, and later (C9 only) the signed contract and
production credentials. None is requested now.
